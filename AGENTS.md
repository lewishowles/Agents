# Agent configuration repo maintenance

This file is for maintaining this repository. It is a local project instruction file for agents working in this repo; it is not generated by this repo and is not installed as an output of this repo.

The generated outputs are `dist/claude/CLAUDE.md`, `dist/codex/AGENTS.md`, and the ChatGPT files under `dist/chatgpt/`.

Source of truth for Claude Code + OpenAI Codex CLI global configuration. Skills, hooks, and rules live here and are distributed to `~/.claude/`, `~/.agents/`, and `~/.codex/` via symlinks.

## Purpose

Single source for shared rules and skills. `scripts/sync-external-skills.sh` refreshes managed official skills; `scripts/sync.sh` composes agent-specific output files (`dist/claude/CLAUDE.md`, `dist/codex/AGENTS.md`) from content in `src/rules/`.

**Current:** `src/` (`src/rules/`, `src/skills/`, `src/hooks/`, `src/adapters/`, `src/fragments/`), `dist/claude/`, `dist/codex/`, `dist/chatgpt/`, `scripts/`, `templates/`, and `docs/`. Dual-target phases are complete; deferred hook ideas remain in root `PROGRESS.md`.


## Where to start

- Shared rule content (applies to both Claude Code and Codex) → `src/rules/*.md`
- Claude-only preamble fragments → `src/fragments/claude/`
- Codex-only preamble fragments → `src/fragments/codex/`
- Regenerating `CLAUDE.md`/`AGENTS.md` from source → `scripts/sync.sh`
- A shared or managed skill → `src/skills/<group>/<name>/skill.json` + `SKILL.body.md`
- This repo's own maintenance skill → `.claude/skills/agent-config/SKILL.md`
- Project scaffolding templates (`AGENTS.md`, `WORKSPACE.md` starting points) → `templates/`
- `WORKSPACE.md` generation logic → `scripts/init-workspace.py`
- Project setup / symlink wiring → `scripts/setup-project.sh`, `scripts/setup-global.sh`

## Confirmed Codex behaviour

- **Global rules:** `~/.agents/AGENTS.md`
- **Project rules:** walks root → cwd for `AGENTS.md`; root real file or symlink covers both runtimes
- **Skills:** `~/.agents/skills/` for this machine's global shared skills; frontmatter `name`+`description` visible upfront; full skill loaded on use
- **Skill discovery:** description-driven, not slash-command; `Use this skill when` plus action-led wording and file globs in description = better matching
- **Hooks:** Codex hooks exist but parity is out of scope; skill descriptions carry discovery weight instead

## Edit workflow

Edit source files here in the repo. Symlinks propagate immediately. After editing `src/rules/` or `src/fragments/<agent>/` content, run `scripts/sync.sh` to regenerate `dist/claude/CLAUDE.md` and `dist/codex/AGENTS.md`. Run `scripts/sync-external-skills.sh` to refresh managed official skills. Commit changes here.

Skills listed in `external-skills.json` are upstream-managed: never hand-edit or paraphrase their content under `src/skills/`. Take changes upstream, then re-run `scripts/sync-external-skills.sh`.

Don't edit `~/.claude/` or `~/.agents/` directly — changes won't persist.

## Skill structure

Shared global skills: `src/skills/<group>/<name>/` — flat groups such as `vue/`, `swift/`, `testing/`, `writing/`, `project-management/`. Each skill has:

- `skill.json` — canonical metadata: `name`, `description` (`Use this skill when` + action-led wording + globs, written for both Claude auto-trigger and Codex description-driven discovery), `triggers`, `filePatterns`, `capabilities`, `dependencies`
- `SKILL.body.md` — the editable instructional content

`scripts/build/build-skill-mds.py` generates `dist/skills/<name>/SKILL.md` (frontmatter from `skill.json` + body from `SKILL.body.md`) — never author `dist/skills/` directly. The `global-rules` skill is the one exception: it has no `SKILL.body.md`; its body is composed straight from `src/rules/global-rules.md`, `identity.md`, `skills-policy.md`, and `file-discovery.md` so it can't drift from the source rules.

Managed external skills also live under `src/skills/<name>`, but are listed in `external-skills.json` and include `SYNC.md`. Do not edit their generated `SKILL.md` files directly — edit `SKILL.body.md` and re-run sync.

## Adding a skill

1. Create `src/skills/<group>/<name>/skill.json` + `SKILL.body.md`
2. Run `bash scripts/sync.sh` — regenerates `dist/skills/`, settings, docs, and other dist targets
3. Check `bash scripts/validate.sh` exits 0
4. Re-run `setup-global.sh` if this is a new skill directory, to create its symlink
